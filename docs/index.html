Less tool switching. More doing.

From a question to a data change.

For developers who need to understand a schema, debug a query, or fix a row — all in the same workspace.

01 / EXPLORE

Find your way around.

Browse tables and database objects, inspect structure, and view relationships in an ER diagram. Use the command palette to move through your workspace.

02 / QUERY

Get to the answer.

Write SQL with syntax colors, run a selection, inspect an execution plan, and keep useful queries in history or saved folders.

03 / EDIT

Make changes deliberately.

Edit cells in place, or stage edits to review before applying. Environment labels, read-only connections and destructive-query confirmations support careful work.

Guardrails support your workflow; database permissions and backups remain essential. Undo covers supported edits, not every SQL statement.

Before you connect

A few practical details.

Is dboard free to use?

The source is available under the MIT license. You can build it yourself and modify it; third-party dependencies retain their own licenses.

What has been tested?

PostgreSQL 16, MariaDB 10.11 and MongoDB have been tested. MongoDB user management has not yet been verified. Windows builds run in CI but have not been manually validated. See the developer guide for current limitations.

Does editing a cell write immediately?

In immediate mode, confirming an edit writes to the database. Staged mode lets you review pending cell edits before applying them. Start with a local database and use a read-only connection when you only need to inspect data.

How can I help?

Try dboard on your platform, report a reproducible issue using sanitized example data, or submit a focused improvement. The contribution guide explains the repository, setup and checks.
